## Python receipt reads and explicit fences

Reuse an existing caller-owned authenticated connection and the exact original
serialized Create from the same qualified release:

```python
from openshell import (
    CreateOwnershipClient,
    create_ownership_key_from_request,
)

ownership = CreateOwnershipClient.from_sandbox_client(connection)
key = create_ownership_key_from_request(original_wire, schema_digest)
receipt = ownership.get(
    "workspace-a",
    key,
    expected_sandbox_id=expected_sandbox_id,
)
```

The client retains the connection's TLS/bearer authentication and per-RPC timeout.
It checks Health for each operation and sends the receipt read once without
Create, replacement lookup or fence fallback. Missing capability and malformed
or contradictory receipts raise ValueError; transport errors retain their gRPC
status through GatewayError. Unknown and incomplete evidence never becomes absence.

`ownership.fence("workspace-a", key)` is a separate explicitly authorized metadata
mutation, not cancellation or runtime absence proof. A lost reply is an error;
read back with `get` rather than automatically resending the fence or Create.
The supplied channel must not contain mutation-retry policies/interceptors.
Health cannot eliminate a later downgrade race; the server must enforce the contract.

Results are frozen domain records with independent bytes and tuples, exact integer
versions and seconds/nanoseconds timestamps. No receipt method closes the caller's
connection, and `complete` describes only the Create result, never broker drainage.
Owned generated-channel/vector tests do not qualify installed runtime or a wheel.
