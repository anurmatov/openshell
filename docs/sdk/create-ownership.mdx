This source is incomplete and advertises neither ownership capability.

- Qualified namespace: immutable provenance for a newly initialized database, not an empty-object inference on upgrade
- Audited Create: original caller, named workspace, canonical UUID and descriptor-projected fingerprint bound before detached execution
- Resource commit: initial Sandbox, immutable binding and mutation target in one transaction before the driver effect marker
- Terminal result: success with a retained binding, or NO_RESOURCE only after an ended owner without a binding or effect
- Uncertain outcome: pending ownership retained after lost completion, caller cancellation or driver uncertainty, with no Create replay
- Explicit fence: ABANDONED for a qualified never-admitted key, otherwise FENCED_PENDING while its owner can still finish
- Receipt reads: fresh authorization and SELECT-only snapshots, with contradictory terminal records refused rather than repaired
- Retention: 24-hour successful receipts and replay-cache completion, with permanent UUID fences and bindings after cache/resource deletion
- SDK wire: canonical Go/Python/TypeScript generation and per-operation capability checks on existing Rust receipt/fence methods

Trusted observers, retained terminal driver journals, curated cross-SDK conformance and remaining source oracles are still pending.
