`GetSandboxCreateReceipt` is SELECT-only, while `FenceSandboxCreate` is an explicit metadata operation that closes admission without cancelling an existing owner; both require fresh named-workspace authorization and bind the authenticated provider/issuer/subject to the original UUID, fingerprint and compiled schema.

Rust workspace clients check `sandbox-create-ownership-v1` on the configured gateway for each call and send no receipt/fence RPC on downgrade, with no automatic fence retry, while missing or unqualified history is refused rather than reported absent and a committed binding never implies driver completion, readiness or broker drain.

This source is incomplete and advertises neither ownership capability: audited Create, coverage initialization, effect completion, other-language generated SDK qualification, trusted observers and retained terminal journals remain pending, with PostgreSQL and installed SQL/image/runtime/restore acceptance separate and `BROKER_BARRIER_UNQUALIFIED` unchanged.
